TDD is a design tool, not a testing tool

Most teams adopt test-driven development hoping for fewer bugs. That is a side effect. The real payoff is the pressure it puts on your design — every hard-to-write test is a design smell talking to you.

## Listen to the friction

When a test needs five mocks to set up, the code under test is doing too much. The test is not the problem — it is the messenger.

# red → green → refactor
def test_price_includes_tax():
    assert price_with_tax(100) == 120
Write the test you wish you had, then make the code deserve it.

Done well, the suite becomes an executable spec — and the design stays honest because it has to.
